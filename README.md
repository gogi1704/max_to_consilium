# MAX-бот для входа в «Консилиум»

Минимальный бот для мессенджера MAX на Python-библиотеке `maxapi`. У него одна
функция: получить у API `ai_project` одноразовую ссылку для входа и отправить её
пользователю кнопкой.

Под кнопкой входа есть кнопка **«Не работает ссылка»**. Она запрашивает новую
одноразовую ссылку и заменяет ссылку в том же сообщении.

Поддерживаются два сценария:

- пользователь нажимает **Начать** или отправляет `/start` — получает ссылку для
  входа существующего MAX-пользователя либо создания нового профиля;
- пользователь приходит с сайта по deep-link с токеном — MAX-профиль
  привязывается к уже открытому профилю «Консилиума».

MAX ID берётся только из подписанного события Bot API. Секрет интеграции
пользователю не передаётся.

## Требования

- Python 3.10 или новее;
- запущенный и доступный `ai_project`;
- чат-бот, созданный на платформе MAX для партнёров.

## Установка и запуск

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env`:

```dotenv
MAX_BOT_TOKEN=ТОКЕН_БОТА_MAX
CONSILIUM_API_URL=http://127.0.0.1:8000
BOT_INTEGRATION_SECRET=ТОТ_ЖЕ_СЕКРЕТ_ЧТО_В_AI_PROJECT
```

Запустите:

```powershell
.\.venv\Scripts\python.exe bot.py
```

Или используйте `start.bat`.

Для production укажите публичный адрес:

```dotenv
CONSILIUM_API_URL=https://consilium.chelovecbitmax.ru
```

Бот работает через long polling. При запуске он автоматически отключает ранее
настроенный webhook, не удаляя ожидающие события, чтобы два режима не
конфликтовали.

## Как проходит регистрация

1. Пользователь нажимает **Начать** в MAX или отправляет `/start`.
2. Бот получает `user_id` из подписанного события MAX и отправляет его в
   `ai_project`. Введённые пользователем числа не используются как MAX ID.
3. Консилиум находит ранее привязанный `chel_id` или создаёт новый.
4. Пользователь получает одноразовую кнопку входа. После открытия сервер создаёт
   длительную браузерную сессию, поэтому анкета и диалоги сохраняются.
5. На другом устройстве пользователь снова нажимает **Начать** и входит в тот же
   профиль. Очистка cookie также не удаляет профиль: повторный вход через MAX его
   восстановит.

Если пользователь начал анкету анонимно, а затем выбрал вход через MAX на сайте,
сайт создаст deep-link. Его `start`-параметр будет передан событием `BotStarted`,
и MAX-профиль привяжется именно к уже заполненной анкете.

Кнопка **«Не работает ссылка»** создаёт новую одноразовую ссылку в том же
сообщении. Старая ссылка при этом не даёт войти в чужой профиль.

## Локальная проверка

1. Запустите `ai_project` на `http://127.0.0.1:8000`.
2. Убедитесь, что `BOT_INTEGRATION_SECRET` в `.env` обоих проектов совпадает.
3. Запустите `start.bat` в этом проекте.
4. В MAX откройте бота и нажмите **Начать**.
5. Нажмите **Войти в Консилиум**. После входа в меню пользователя должна
   отображаться привязка MAX.
6. Закройте сайт, снова нажмите **Начать** в MAX и проверьте, что открывается тот
   же пользователь с прежней анкетой и диалогами.

Автоматические тесты:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Запуск в Docker рядом с Консилиумом

Проект использует уже существующую сеть `consilium-internal` и не публикует ни
одного порта сервера. Поэтому он не конфликтует с `anketa_bot_max`,
`bitrix_connector` и другими контейнерами.

Для Docker замените адрес API в `.env`:

```dotenv
CONSILIUM_API_URL=http://consilium:8000
HEALTHCHECK_FILE=/tmp/consilium-max-bot.heartbeat
HEALTHCHECK_MAX_AGE=120
```

Затем выполните из каталога `max_to_consilium`:

```bash
docker-compose config
docker-compose up -d --build
docker-compose ps
docker-compose logs --tail=100 consilium-max-bot
```

Контейнер должен перейти в состояние `healthy`. Для обновления кода достаточно:

```bash
git pull
docker-compose up -d --build
docker-compose ps
```

Не добавляйте MAX-бота в `docker-compose.yml` других проектов и не меняйте их
порты. Общая точка соприкосновения — только внутренняя сеть
`consilium-internal` и API `http://consilium:8000`.

## Настройка ai_project

В `.env` проекта `ai_project` должны быть заданы:

```dotenv
BOT_INTEGRATION_SECRET=ТОТ_ЖЕ_СЕКРЕТ_ЧТО_У_БОТА
MAX_BOT_AUTH_URL=https://max.ru/ИМЯ_БОТА?start={token}
```

После изменения перезапустите `ai_project`. Параметр `{token}` обязателен:
backend подставляет в него одноразовый токен привязки.

## API-контракт

Бот вызывает:

```http
POST /api/auth/messenger/link
Authorization: Bearer BOT_INTEGRATION_SECRET
Content-Type: application/json
```

```json
{
  "provider": "max",
  "provider_user_id": "123456789",
  "intent_token": ""
}
```

В ответ ожидается JSON с полем `auth_url`.

## Важное замечание для production

Текущая версия использует long polling — это удобно для локального теста и
первого запуска. Документация MAX рекомендует Webhook для production-нагрузки.
Переход на Webhook можно сделать отдельным этапом после проверки регистрации:
он потребует отдельного HTTPS-маршрута и настройки подписки MAX.
